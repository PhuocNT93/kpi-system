## Test Cases

| ID | Scenario | Preconditions | Action | Expected Result |
|---|---|---|---|---|
| **TC-VAL-01** | Upload payload missing required fields | User is HR_ADMIN; Cycle and employees exist | POST `/api/evaluation-data/imports` with payload missing `employee_code`, `kpi_code`, or `value` | HTTP 400 Bad Request; validation errors specify the missing required fields; import is not staged |
| **TC-VAL-02** | Staging payload with invalid/inactive employee or non-existent cycle | User is HR_ADMIN | POST `/api/evaluation-data/imports` with non-existent `cycle_id` or non-existent `employee_code` | Staged import created in status `INVALID`; staged record status is `INVALID` with specific `error_message`; Apply is blocked |
| **TC-VAL-03** | Staging payload missing rationale or source_snapshot | User is HR_ADMIN | POST `/api/evaluation-data/imports` where a KPI record has empty rationale or missing source_snapshot object | HTTP 400 Bad Request; Zod schema rejects payload; explanation indicates rationale and source_snapshot are mandatory |
| **TC-RES-01** | 3-Tuple Entity Resolution across multiple cycles | Employee EMP001 has evaluations in Cycle Q1-2026 and Cycle Q2-2026 with same KPI `KPI_DELIVERY` | POST `/api/evaluation-data/imports` containing records for EMP001 targeting Q1-2026 and Q2-2026 | System accurately resolves distinct `evaluation_item` records matching `(cycle_id, employee_id, kpi_code)` without cross-cycle pollution |
| **TC-CONF-01** | Competing KPI values within same import batch | User is HR_ADMIN; Import payload contains 2 conflicting entries for same employee, cycle, and KPI (e.g., Jira vs Google Sheet) | POST `/api/evaluation-data/imports` | Staged import status is `CONFLICT`; record `conflicts` contains side-by-side values; status is `CONFLICT`; apply is blocked |
| **TC-CONF-02** | Resolving conflict via draft edit | Import is in `CONFLICT` status | PATCH `/api/evaluation-data/imports/:id` with resolution `USE_INCOMING` | Conflict marked resolved; record status becomes `VALID`; import status transitions `CONFLICT` $\rightarrow$ `READY` |
| **TC-IDEMP-01** | Idempotent Apply call (Sequential retry) | Import status is `READY` | Call POST `/api/evaluation-data/imports/:id/apply` twice sequentially | First call returns HTTP 200 with applied summary; second call returns HTTP 200 with identical summary; no duplicated `evidence` rows, no re-scoring, no duplicate audit records |
| **TC-CONC-01** | Concurrent Apply attempts (Race condition protection) | Import status is `READY` | Two concurrent threads send POST `/api/evaluation-data/imports/:id/apply` at the exact same moment | First thread acquires row lock, transitions status to `APPLYING`; second thread receives HTTP 409 Conflict ("Import is currently being processed") |
| **TC-LOCK-01** | Cycle locked before Apply | Evaluation cycle has `status = 'LOCKED'`; import status is `READY` | HR_ADMIN calls POST `/api/evaluation-data/imports/:id/apply` | Transaction lock inspects cycle status; all rows rejected with `error_message = 'EVALUATION_CYCLE_LOCKED'`; import status is `FAILED`; no mutations committed |
| **TC-LOCK-02** | Evaluation published / locked during chunked batch apply | Import contains 150 records: 100 for open cycle/draft evaluation, 50 for an evaluation in `PUBLISHED` status | HR_ADMIN calls POST `/api/evaluation-data/imports/:id/apply` | Open evaluations updated and scored; published evaluations rejected with `EVALUATION_ALREADY_PUBLISHED`; import transitions to `PARTIALLY_APPLIED`; `success_count = 100`, `error_count = 50` |
| **TC-APPLY-01** | Full Happy Path Apply | Cycle is ACTIVE, import status is `READY` with 10 records and 15 evidence items | HR_ADMIN calls POST `/api/evaluation-data/imports/:id/apply` | Import status becomes `APPLIED`; `evaluation_item` records updated with `measurement_value`, `comment`, `rationale`, `import_id`, `source_snapshot`; 15 `evidence` records inserted with status `ACTIVE`; staging `final_evidence_id` linked |
| **TC-SCORE-01** | Scoring Engine & Rule Engine execution post-apply | Evaluations have pre-existing items; import applies new measurement values | Apply completes successfully | `EvaluationService` runs Rule Engine and Scoring Engine; `weighted_score` and `overall_score` recalculated using exact pipeline; rounding `ROUND_HALF_UP` verified; audit log contains `IMPORT_APPLY` |
| **TC-PROJ-01** | Reporting Read Model Projection | Evaluation applied and scored | Service emits `EVALUATION_UPDATED` event | `ReportingProjectionService` projects to `employee_kpi_score_read_model`: `has_evidence = TRUE`, `evidence_count` matches active evidence count, `comment` is populated |
| **TC-IMMUT-01** | Evidence Append-Only & Supersede enforcement | Evidence E01 exists with status `ACTIVE` | (a) Direct API attempt to UPDATE or DELETE E01; (b) Replacement evidence applied for same KPI | (a) Denied (no update/delete endpoint); (b) E01 status updated to `SUPERSEDED`, `superseded_by` points to new evidence ID, `superseded_at` is recorded; old evidence remains intact |
| **TC-RBAC-01** | Mutation endpoints restricted to HR_ADMIN | User authenticated as SYSTEM_ADMIN | Send POST `/api/evaluation-data/imports`, PATCH `/api/evaluation-data/imports/:id`, or POST `/api/evaluation-data/imports/:id/apply` | HTTP 403 Forbidden on all mutation endpoints (System Admin is strictly read-only) |
| **TC-RBAC-02** | Mutation endpoints restricted from EMPLOYEE / MANAGER | User authenticated as EMPLOYEE or MANAGER | Send POST `/api/evaluation-data/imports/:id/apply` | HTTP 403 Forbidden |
| **TC-RBAC-03** | Explainability endpoint - Employee self access | Employee E01 requests `/api/evaluations/:evalId/kpis/:code/evidence` for an evaluation belonging to E01 | Authenticated GET request | HTTP 200 OK; returns full Explainability View DTO |
| **TC-RBAC-04** | Explainability endpoint - Employee peer access blocked | Employee E01 requests `/api/evaluations/:evalId/kpis/:code/evidence` for an evaluation belonging to Employee E02 | Authenticated GET request | HTTP 403 Forbidden |
| **TC-RBAC-05** | Explainability endpoint - Manager team scope | Manager M01 requests `/api/evaluations/:evalId/kpis/:code/evidence` for direct report | Authenticated GET request | HTTP 200 OK |
| **TC-RBAC-06** | Explainability endpoint - Manager other team blocked | Manager M01 requests `/api/evaluations/:evalId/kpis/:code/evidence` for employee in another department | Authenticated GET request | HTTP 403 Forbidden |
| **TC-RBAC-07** | Explainability endpoint - HR_ADMIN / SYSTEM_ADMIN org scope | HR_ADMIN or SYSTEM_ADMIN requests `/api/evaluations/:evalId/kpis/:code/evidence` for any employee | Authenticated GET request | HTTP 200 OK |
| **TC-UI-01** | Frontend UI States on Import Page | HR Admin navigates to `/imports/evaluation-data` | Test page under 4 states: Loading, Error, Empty, and Forbidden | Component gracefully renders skeletons, error alerts, empty state illustrations, or 403 access denied banner |
